# 0. 원칙 — 기준 체계의 뿌리

바람대로의 기준은 두 층이다. 섞으면 시방서 개정이 카피 규칙까지 흔든다.

```
1층  작업 기준   현장에서 어떻게 시공·세척하나   → docs/standards/1-작업기준.md ⚠️ 미추적
2층  발화 기준   그걸 밖에 어떻게 말하나        → docs/standards/2-발화기준.md
     데이터 기준 무엇을 어떤 규격으로 남기나     → docs/standards/3-데이터기준.md
```

> ⚠️ **1-작업기준.md와 `src/content/site/workstandard.json`은 이 레포에 없다.**
> 제3자 문서(삼성전자서비스 표준시방서 2025)의 실질 내용을 담아, PUBLIC 레포의
> git 히스토리에 남기지 않기로 했다 (2026-08-25). `.gitignore` 등재.
> **보관처: `~/repos/company/_archive/baramdaero-standards/`** — 배치·복구는 그곳 `README.md`.
> 아래 문서들이 1의 A5·B1·C4 같은 항목을 참조하는 것은 그 사본 기준이다.

## 원칙 3개

**1. 말한 것은 지킨다. 지킬 수 없는 것은 말하지 않는다.**
모든 기준의 뿌리다. 카피가 작업을 앞서가지 못한다.

**2. 사실에는 출처가 있다. 출처 없는 수치는 쓰지 않는다.**
인용 우선순위: 제조사 시방서 > 공공기관 > 자사 실측.
인용 불가: 블로그·전언.

**3. 기록이 기준을 만든다.**
지금 기준은 시방서 차용이다. 자사 실측이 쌓이면 우리 숫자로 교체한다.
교체 전까지 모든 차용 기준에는 출처를 밝힌다.

## 우선순위

충돌하면 이 순서로 판정한다.

```
안전 > 법규 > 고객 약속 > 브랜드 톤 > 효율
```

## 층 사이의 단방향 규칙

1층에 있다고 2층에서 쓸 수 있는 것은 아니다.
차용한 시방서 조항 중 자사 이행 능력이 확인되지 않은 항목(기간·무상·범위 약속)은
1층에 남기되 2층으로 내보내지 않는다. 실제 사례는 1-작업기준.md 「차용하지 않는 조항」 참조.

## 문서 위상

- 이 4개 문서가 기준의 단일 원본(SSOT)이다.
- `src/content/site/workstandard.json`은 1-작업기준.md의 **추출본**이다.
  값이 어긋나면 md가 이긴다. 둘 다 미추적 — 위 경고 참조.
  사이트에 장비·약품 수치를 실제로 노출하기로 결정하면, **노출할 값만** 별도로
  추적 파일에 옮긴다. 추출본 전체를 공개 레포로 되돌리지 않는다.
- 레포 규칙(`CLAUDE.md`)·디자인 규칙(`DESIGN.md`)과 충돌하면
  안전·법규는 이 문서가, 코드·스타일 절차는 각 레포 문서가 이긴다.
