# 3. 데이터 기준 — 기록 규격

9월부터 쌓을 기록의 규격이다. 여기 쌓인 값이 1-작업기준.md의 D등급 빈칸과
`standards.json`의 기준가를 채운다 (0-원칙 3).

**전제**: 기록하지 않은 것은 말할 수 없다 (2-발화기준.md §2 「근거 없는 수치」).

---

## 1. 개인정보 규칙 (절대)

`src/content/cases/README.txt`가 원본이며 동일 규칙을 전 기록에 적용한다.

- 단지명·동호수·상세주소·고객명 기재 금지. 지역은 **시·구까지만** (예: 서울 강서)
- 건물은 **유형까지만** (예: 구축 아파트 30평형대)
- 사진은 **장비·천장·배관만**. 현관문·문패·차량 번호판·사람이 나온 사진 금지

---

## 2. 시공 기록

| 항목 | 규격 |
|---|---|
| 기종 | 4way 카세트 / 1way / 매립형 / 벽걸이 / 스탠드 / 실외기 |
| 대수 | 정수 |
| 지역 | 시·구 (예: 경기 부천) |
| 작업 시작·종료 시각 | 실측. `HH:MM` 두 값을 따로 적는다 (소요시간만 적으면 검증이 안 된다) |
| 인원 | 정수 |
| 특이사항 | 자유 서술 |
| 사진 | §5 촬영 규격 |
| 공개 동의 | 있음 / 없음 — **없음이면 사례로 쓰지 않는다** |

사이트 반영 시 `src/content/cases/*.md` 프론트매터로 옮긴다
(`work.duration`은 실측값만, 없으면 비운다).

---

## 3. 세척 기록

시공 기록 전 항목 + 아래.

| 항목 | 규격 |
|---|---|
| 분해 범위 | 1-작업기준.md B1의 단계 번호로 적는다 (예: 1~16 전 단계 / 1~8만) |
| 오염 상태 (전) | 서술 + 사진 |
| 오염 상태 (후) | 서술 + 사진 |
| 사용 약품 | 제품명 + 인증 근거 (A5 대조) |
| 표준 절차 이탈 | B등급 조정 시 **무엇을 왜 바꿨는지**. 없으면 "없음" |

---

## 4. AS 기록

| 항목 | 규격 |
|---|---|
| 증상 | **고객 표현 그대로** (요약·번역하지 않는다) |
| 확인 순서 | 무엇을 어떤 순서로 봤는지 |
| 원인 | 확정된 것만. 추정이면 "추정"으로 표기 |
| 조치 | 실제로 한 것 |
| 결과 | 해소 / 미해소 / 재방문 필요 |

1-작업기준.md C4(세척이 만드는 고장 3계열)에 해당하는 건은 그 계열을 함께 적는다.
자사 세척이 원인인 건과 아닌 건이 섞이면 기준가·절차 개정 판단이 흐려진다.

## 5. 촬영 규격

### 확정된 것

- 장비·천장·배관만. 집·사람은 프레임에 넣지 않는다 (§1)
- 분해 상태 컷은 필수 (2-발화기준.md ②작업 사진 전달의 실체)
- 전·후는 **같은 각도**에서 찍는다

### 필수 컷 목록 — [9월 확정]

```
[9월 확정] 기종별 필수 컷 목록
[9월 확정] 컷당 최소 해상도·파일 형식

```

확정 조건: 9월 테스트 현장에서 실제 촬영해 본 뒤,
고객 전달분과 사이트 게재분에 각각 무엇이 필요한지 확인하고 채운다.
그 전까지 이 자리는 비워 둔다 — 찍어 보지 않고 정한 목록은 현장에서 안 지켜진다.
