# 쇼핑몰 ↔ 본 사이트 로그인 연결

**상태(2026-10-20): 본 사이트 쪽과 쇼핑몰 Footer Code(v2.1) 모두 적용됨. 쇼핑몰은 이미 공개 상태이고, 로그아웃·로그인 두 상태의 실제 화면에서 확인했다. 아직 못 본 것(일반 회원 계정, 실제 로그인·가입·소셜 로그인 흐름, 휴대폰)은 '더 확인할 것'.**

## 하는 일
본 사이트(baramdaero.com) 헤더·푸터의 '로그인'을 누르면 쇼핑몰(shop.baramdaero.com) 로그인 화면으로 가고,
로그인하면 **누르기 전에 보던 본 사이트 화면으로 돌아온다.** 쇼핑몰에서 로그인한 방문자에게는 본 사이트의 '로그인' 자리에 '마이페이지'가 보인다.
둘은 출처가 달라 서로의 로그인 상태를 읽지 못하므로, 아래 두 가지로만 주고받는다.

## 계약
| 무엇 | 누가 | 내용 |
|---|---|---|
| 쿠키 `bd_login=1` | 쇼핑몰이 켜고 끈다, 본 사이트는 읽기만 | 도메인 `.baramdaero.com`, 7일(쇼핑몰 화면을 열 때마다 갱신), `Secure; SameSite=Lax`. 로그인 표시 하나뿐 — 개인정보 없음 |
| 돌아올 화면 | 본 사이트의 '로그인' 링크(`referrerpolicy="unsafe-url"`)가 보던 주소를 리퍼러로 실어 보낸다 | 쇼핑몰이 로그인 화면(`/login`)에서 `document.referrer`를 읽어 쇼핑몰 `localStorage`(`bd_return`, 10분 — 새 탭·앱 전환으로 돌아와도 남게)에 둔다 |

이 연결(`src/scripts/shop-session.js`)은 쿠키·저장소에 아무것도 쓰지 않고 `bd_login`을 읽기만 한다. 개인정보 처리방침 §8의 "이 사이트는 쿠키를 직접 저장하지 않습니다"와 맞다.
(사이트의 다른 부분이 쓰는 저장소 — 챗봇 안내 말풍선의 `bd_teaser` 등 — 는 별개이고, §8은 쿠키 문구만 다룬다.)
쇼핑몰이 `bd_login`을 남기는 것은 쇼핑몰 쪽 일이라, 쇼핑몰 방침의 쿠키 문구에 넣을지는 별도 판단이다.

**리퍼러로 가는 정보:** '로그인'을 누르면 지금 보던 화면의 전체 주소(쿼리 포함, `#` 뒤는 제외)가 쇼핑몰(같은 회사 사이트)로 간다.
`/cases/`는 입력한 검색어를 주소(`?q=`)에 쓰므로, 쇼핑몰 코드는 저장하기 전에 `q`를 지운다(지역 `r=` 등은 남겨 돌아온 화면이 같게).

본 사이트 쪽 파일: `src/scripts/shop-session.js`(쿠키 읽기 → `<html class="bd-member">`), `SiteHeader.astro`·`SiteFooter.astro`(링크·표시 전환),
`src/config.js`의 `SHOP_MYPAGE_PATH`(비우면 '마이페이지'·표시·스크립트가 모두 빠지고 '로그인'만 남는다).
검사는 `npm run test:shop` — 링크·CSS·스크립트 위치(`check-shop-links.mjs`), 표시 스크립트(`check-shop-session.mjs`), **이 문서의 쇼핑몰 코드를 그대로 꺼내 돌려 보는 시나리오(`check-shop-bridge.mjs`)**.

## 쇼핑몰 Footer Code — v2.1(2026-10-20 적용)
설정 > SEO > 고급 설정 > 공통 코드 삽입 > Footer Code. 채널톡 부트 스크립트(680자)는 그대로 두고 그 아래에 덧붙인 부분만 바꾼다.
- 직전 버전 v1(2026-10-19 적용, 1524자, SHA-256 `a48c1bf53dad22429ebff651b69d97e0f68a333f4664e471cf76a54cec768e74`, Footer Code 총 2205자)은 소셜 로그인 없이 이메일 로그인만 가정한 버전이었다. 2026-10-20 오전에 v2(2252자, SHA-256 `87daa07248fcbdd5da2abb9934da1d9fa08967c8b022b7519ad09c76b654a441`, 총 2933자)로 바꿨고, 같은 날 낮에 아래 사고를 고친 v2.1로 바꿨다.
- **아래 블록은 v2.1**(2669자, SHA-256 `b6273baac13291ad328dffb88f957a446643efd33e05d215f758f90aff68dc35`) — 쇼핑몰 Footer Code에 들어 있는 것과 같다(총 3350자 = 채널톡 680 + 줄바꿈 + 2669). 저장 뒤 새로고침해서 앞 680자와 덧붙인 부분의 해시를 대조했다.
- **고친 사고(2026-10-20):** v1·v2는 `a[href*="logout"]` 링크가 있으면 로그인으로 판단했다. 쇼핑몰이 비공개일 때는 로그아웃 화면을 볼 수 없어 '확인 필요'로 적어 둔 추정이었는데, 쇼핑몰이 공개된 뒤 로그아웃 화면을 보니 **숨은 로그아웃 링크(알림 패널)가 1개 있어** 방문자 모두가 로그인으로 오판됐다 — 쇼핑몰을 열기만 해도 `bd_login`이 켜져 본 사이트에 '마이페이지'가 떴다(내장 브라우저로 재현). v2.1은 아임웹이 화면에 넣는 `window.MEMBER_UID`(로그인 21자 문자열, 로그아웃 빈 문자열)로 판단하고, 값이 문자열이 아니면 아무것도 건드리지 않으며, 변수가 아직 없으면 `load`에서 한 번 더 본다.
- v1과 다른 점(v2부터): 복귀 주소를 `localStorage`에 둔다 / 팝업·틀 안에서는 돌지 않는다 / 복귀 주소를 버리는 판단을 `/login` 입구뿐 아니라 로그아웃 상태의 모든 화면에서 한다(쇼핑몰 안을 돌아다니다 로그인·가입한 경우 튕기지 않게) / 소셜 로그인 제공자·콜백(`/oauth`)·가입 흐름을 거쳐도 기억을 유지 / 저장소 값 검증 강화(미래 시각·엉뚱한 형식·가득 찬 저장소).
검사가 아래 코드를 문서에서 그대로 꺼내 쓰고, 위에 적은 해시·길이가 블록과 같은지도 본다. 고칠 때는 이 블록을 고치고 해시·길이를 다시 적고 쇼핑몰 Footer Code도 같이 바꾼다.

```html
<script>
/* bd-login-bridge v2.1 — 본 사이트(baramdaero.com)와 로그인 상태·돌아올 화면을 주고받는다 (docs/shop-login-bridge.md) */
(function () {
  // 틀(디자인 모드·미리보기)이나 팝업(소셜 로그인 창) 안에서는 돌지 않는다 — 팝업이 본 사이트로 튕기거나 닫히지 않으면 안 된다
  if (window.top !== window.self || window.opener) return;
  var KEY = 'bd_return';
  var COOKIE = '; domain=.baramdaero.com; path=/; SameSite=Lax; Secure';
  var MAIN = /^https:\/\/(www\.)?baramdaero\.com\//;
  var ref = document.referrer;
  // 새 탭·앱 전환으로 돌아와도 남게 localStorage 에 둔다(10분). 먼저 지우고 쓴다 — 저장소가 가득 차 쓰기가 실패해도 옛 기억이 남지 않는다
  var save = function (v) {
    try { localStorage.removeItem(KEY); } catch (e) {}
    try { if (v) localStorage.setItem(KEY, v); } catch (e) {}
  };
  // 낡았거나(미래 시각 포함) 깨졌거나 본 사이트 주소가 아니면 지우고 없는 것으로 본다
  var load = function () {
    try {
      var s = JSON.parse(localStorage.getItem(KEY));
      var age = s && Date.now() - s.t;
      if (s && typeof s.u === 'string' && age >= 0 && age < 600000 && MAIN.test(s.u)) return s.u;
    } catch (e) {}
    save(null);
    return null;
  };
  var run = function () {
    // 로그인 여부 = 아임웹이 화면에 넣는 window.MEMBER_UID (로그인하면 값이 있고 로그아웃이면 빈 문자열 — 2026-10-20 로그인·로그아웃 화면에서 확인).
    // '로그아웃' 링크로 판단하면 안 된다: 로그아웃 화면에도 숨은 로그아웃 링크(알림 패널)가 있어 방문자 모두가 로그인으로 보인다.
    // 값이 문자열이 아니면(변수가 없는 화면) 상태를 모르는 것이므로 쿠키·저장값·이동 어느 것도 건드리지 않는다
    var uid = window.MEMBER_UID;
    if (typeof uid !== 'string') return;
    if (uid === '') {
      document.cookie = 'bd_login=; max-age=0' + COOKIE;
      load();
      try {
        // 쇼핑몰 안의 다른 화면에서 온 경우(리퍼러가 쇼핑몰) — 로그인·소셜 로그인 콜백·가입 흐름 안의 화면은 빼고 본다
        var stray = ref.indexOf(location.origin + '/') === 0 && !/^\/(login|oauth|shop_join)/.test(ref.slice(location.origin.length));
        var fromMain = MAIN.test(ref);
        if (location.pathname === '/login' && fromMain && !location.search) {
          // 본 사이트의 '로그인'을 눌러 로그인 화면에 막 도착했다 — 그 화면을 기억한다(입력한 검색어 q 는 뺀다)
          var u = new URL(ref);
          u.searchParams.delete('q');
          save(JSON.stringify({ u: u.href, t: Date.now() }));
        } else if (stray || (location.pathname === '/login' && fromMain)) {
          // 쇼핑몰 안에서 돌아다니다 시작한 로그인·가입, 보호된 화면(주소에 쿼리)에서 넘어온 로그인 — 돌아갈 곳을 버린다.
          // 로그인 실패 뒤 다시 열린 /login, 소셜 로그인 콜백을 거친 화면, 제공자(카카오·네이버 등) 화면에서 취소하고 돌아온 경우, 리퍼러가 없는 경우는 건드리지 않는다
          save(null);
        }
      } catch (e) {}
      return;
    }
    document.cookie = 'bd_login=1; max-age=604800' + COOKIE;
    var back = load();
    save(null);
    if (back) location.replace(back);
  };
  // 변수가 이 시점에 이미 있으면 바로, 아직 없으면(늦게 생기는 경우) 모든 파일을 불러온 뒤에 한 번 본다
  if (typeof window.MEMBER_UID === 'string') run();
  else window.addEventListener('load', run);
})();
</script>
```

돌려보낼 주소는 `https://baramdaero.com/` 또는 `https://www.baramdaero.com/` 아래만 받는다(다른 주소로 보내는 통로가 되지 않게). 저장된 값을 꺼낼 때도 같은 검사를 한다.

## 소셜 로그인(카카오톡·네이버 등)을 켤 때
관리자 설정 > 고객 > 고객 설정 > 소셜 로그인(`/admin/config/oauth`)에는 카카오싱크·네이버·구글·페이스북·애플·라인이 있고, 2026-10-20 현재 켜진 것은 없다(화면에서 확인). 켜는 것은 이 문서 범위 밖이고, 켠 뒤에도 본 사이트는 바꿀 것이 없다 — '로그인'은 쇼핑몰 로그인 화면으로 가고 거기에 소셜 버튼이 나온다.
조사로 알게 된 것(아임웹 공식 설명이 아니라 공개 글 기준이며 이 쇼핑몰에서는 확인 안 됨): 카카오싱크는 사업자등록번호가 필요하고, 카카오 앱을 직접 쓰면 Redirect URI에 사이트 주소 + `/oauth`(여기서는 `https://shop.baramdaero.com/oauth`)를 등록해야 하며, 네이버 등 제공자의 콜백 주소는 `https` 여야 한다.

소셜 로그인은 로그인 화면에서 제공자 화면으로 나갔다 돌아오는 흐름이라, 복귀 코드는 아래 방식들을 모두 견디게 짰다. **아임웹이 실제로 어느 방식인지는 켜 본 뒤에야 안다**(확인 안 됨).

| 흐름 | 코드가 하는 일 |
|---|---|
| 같은 탭에서 제공자 화면으로 나갔다 쇼핑몰 콜백(`/oauth`로 추정)으로 돌아옴 | `/login`에서 저장 → 콜백 화면은 로그인 전이라 건드리지 않음 → 로그인된 첫 화면에서 돌아옴 |
| 제공자 화면에서 취소하고 `/login`으로 돌아옴(리퍼러가 제공자, 쇼핑몰 콜백, 또는 없음) | 기억 유지 — 쇼핑몰 안의 다른 화면에서 온 경우만 버린다 |
| 소셜 로그인이 팝업 창으로 열림 | 팝업(`window.opener`가 있는 창)에서는 아무것도 하지 않는다 — 안 그러면 팝업이 본 사이트로 튕긴다. 원래 창이 로그인 뒤 새로고침되면 거기서 돌아온다 |
| 새 탭·앱 전환으로 같은 브라우저에서 돌아옴 | `localStorage`라 남아 있다 |
| 처음 가입(추가 정보 입력) | 가입 흐름 안의 화면(`/shop_join`…)은 기억을 건드리지 않고, 가입을 마친 첫 화면에서 돌아온다 |
| 카카오톡·네이버 앱 안 브라우저에서 시작해 다른 브라우저로 돌아옴 | 저장소가 브라우저마다 따로라 돌아오지 못하고 쇼핑몰에 머문다(로그인은 정상, 확인 안 됨) |

## 확인한 것 (2026-10-20, v2.1을 넣은 날, 로그아웃·로그인 두 상태, 실제 화면)
- **저장·대조:** 저장 알림을 확인했고, 새로고침 뒤 Footer Code는 3350자, 앞 680자(채널톡)와 줄바꿈은 그대로, 덧붙인 부분(2669자)의 SHA-256이 위 값과 같고 v2 표시는 없다. Header Code(56,257자)와 다른 편집기는 그대로다.
- **로그아웃(시크릿과 같은 내장 브라우저):** 쇼핑몰 홈에서 `MEMBER_UID`는 빈 문자열이고 숨은 로그아웃 링크는 DOM에 1개 있지만 방문자로 판단한다. v2가 켜 둔 가짜 `bd_login` 쿠키는 쇼핑몰을 열자 지워졌다. 본 사이트(`/care/`)는 헤더·푸터 모두 '로그인'이고 `bd-member` 클래스가 없다. 본 사이트에서 '로그인'을 누르면 쇼핑몰 `/login`이 돌아올 주소를 저장하고(검색어 `q`는 빠지고 지역 `r`은 남음, 로그인 표시 쿠키는 안 켜짐), `/login` → 쇼핑몰 홈(리퍼러가 `/login`)에서는 그 저장을 유지하며, 쇼핑몰 홈 → 장바구니(리퍼러가 일반 쇼핑몰 화면)에서는 버린다.
- **로그인(관리자 계정, 내 크롬):** `MEMBER_UID`는 21자 문자열이다. 지운 `bd_login`을 v2.1이 다시 켜고 채널톡도 정상이다. 맞는 본 사이트 주소(`/faq/`)가 저장돼 있으면 돌아오고 본 사이트 헤더가 '마이페이지'이며, 다른 사이트(`example.com`)·미래 시각 저장값은 따르지 않고 지운다. 본 사이트에서 '마이페이지'를 누르면 쇼핑몰 마이페이지에 머물고, 로그인한 채 `/login`을 열면 쇼핑몰 홈으로 되돌려지고 저장값은 남지 않는다.
- **아직 못 본 것:** 일반 회원(관리자가 아닌 고객) 계정의 `MEMBER_UID` 값, 실제 비밀번호 로그인·가입·소셜 로그인 흐름, 휴대폰 실기기.

## 확인한 것 (2026-10-20, v2를 넣은 날, 관리자 로그인 상태, 실제 화면)
- **저장·대조:** 저장 알림을 확인했고, 새로고침 뒤 Footer Code는 2933자, 앞 680자(채널톡)와 줄바꿈은 그대로, 덧붙인 부분(2252자)의 SHA-256이 위 값과 같고 v1 표시는 없다. Header Code(56,257자)와 다른 편집기(robots·llms·Header 상단·Body)는 그대로다.
- **실제 화면:** 쇼핑몰 화면에 v2 스크립트가 한 번 들어 있고, `bd_login`을 지운 뒤 쇼핑몰 화면을 열면 v2가 다시 켠다. 채널톡도 정상이다. 로그인한 채 `/login`을 열면 쇼핑몰 홈(`/`)으로 되돌려지고 저장값은 남지 않는다.
- **돌아오기:** 맞는 본 사이트 주소(`/faq/`)가 저장돼 있으면 로그인된 쇼핑몰 화면을 열자마자 돌아오고 본 사이트 헤더가 '마이페이지'다. 미래 시각·본 사이트가 아닌 주소(`example.com`)·주소가 배열인 저장값은 따르지 않고 지운다. 본 사이트에서 '마이페이지'를 누르면 쇼핑몰 마이페이지에 머물고 튕기지 않는다.
- **팝업:** 쇼핑몰 화면의 버튼을 눌러 연 팝업 창(`window.opener`가 있는 창)이 로그인된 `/shop_mypage`에서 본 사이트로 가지 않고 머물렀고, 저장값도 건드리지 않았다. 실제 소셜 로그인 팝업은 켠 뒤에 본다.

## 확인한 것 (2026-10-19, v1을 넣은 날, 관리자 로그인 상태)
- **로그인 판별:** 로그인한 쇼핑몰 홈·`/shop_mypage`에서 `a[href*="logout"]`이 4개 잡힌다(`/logout.cm?back_url=…` — 아임웹 `back_url`은 경로를 base64 한 값). 로그인 상태의 화면에는 로그인 링크가 아예 없다(서버가 가려서 그린다). **다만 이 로그아웃 링크는 로그아웃 화면에도 숨어 있어 판별에 쓸 수 없다**(위 '고친 사고').
- **마이페이지 주소:** `/shop_mypage`가 맞다(헤더 메뉴의 `마이페이지` 링크). 로그인한 채 `/login`을 열면 쇼핑몰 홈(`/`)으로 되돌려진다.
- **저장(v1):** 저장 알림을 확인했고, 새로고침 뒤 Footer Code는 2205자, 앞 680자(채널톡)는 그대로, 덧붙인 부분의 해시는 v1 값과 같았다. Header Code(56,257자)는 건드리지 않았다.
- **실제 화면:** 쇼핑몰 화면에서 스크립트가 한 번 실행되어 `bd_login`이 켜졌고, 본 사이트(`/care/`)의 헤더·푸터가 '마이페이지'로 바뀌었다(`.baramdaero.com` 쿠키를 본 사이트에서 읽음). '마이페이지'를 누르면 쇼핑몰 마이페이지가 열리고 튕기지 않는다. 채널톡도 정상이다.
- **돌아오기(꺼내 쓰는 쪽, v1):** 저장된 복귀 주소가 본 사이트면 로그인된 쇼핑몰 화면을 열자마자 그 화면으로 돌아오고(`/faq/`로 확인), 본 사이트가 아닌 주소(`example.com`)는 따르지 않고 저장값만 지운다.

## 더 확인할 것 (아직 못 본 것)
쇼핑몰은 2026-10-20 공개 상태다(로그아웃 방문자에게 실제 상점이 보인다). 로그아웃 상태 화면은 위에서 확인했고, 아래는 **테스트 회원 계정과 실제 로그인이 있어야** 볼 수 있다.
1. **일반 회원(관리자가 아닌 고객) 계정의 `MEMBER_UID`**: 테스트 회원으로 로그인해 값이 비어 있지 않은지(관리자 계정으로만 확인했다). 비어 있으면 그 회원은 로그인한 사람으로 안 보인다 — 판별을 바꾸고 `check-shop-bridge.mjs`의 가짜 화면도 같이 고친다.
2. 본 사이트 아무 화면 → '로그인' → 쇼핑몰 `/login`(복귀 주소 저장 — 이 부분은 확인함) → 실제로 로그인 → **눌렀던 본 사이트 화면으로 돌아오고** 헤더가 '마이페이지'.
3. 비밀번호를 일부러 틀리고 다시 입력해 로그인 → 그래도 돌아온다.
4. 본 사이트 '로그인' → 쇼핑몰의 가입 화면으로 갔다가 가입 완료 → 돌아온다(가입 후 이동은 '마지막 접속 메뉴'로 켜 둠).
5. 쇼핑몰의 장바구니·구매 화면에서 시작한 로그인은 쇼핑몰에 머문다(본 사이트로 가지 않는다).
6. 쇼핑몰에서 로그아웃 → 본 사이트로 가면 다시 '로그인'(뒤로 가기로 돌아가도 바뀌어 있다).
7. 디자인 모드 편집 화면(틀 안)에서 코드가 돌지 않는지 — `window.top` 검사로 막아 두었다. 편집 중 화면이 튕기면 바로 코드를 지운다.
8. 휴대폰 폭(헤더·푸터 둘 다), 사파리·크롬.
9. **소셜 로그인을 켠 뒤** 카카오톡·네이버 각각 — 화면 이동인지 팝업인지, 콜백 경로(`/oauth`로 추정)와 로그인 뒤 이동 위치, 제공자 화면에서 취소하고 돌아왔을 때 복귀 주소가 유지되는지, 처음 가입할 때 거치는 화면의 경로, PC·휴대폰, 카카오톡·네이버 앱 안 브라우저와 앱 전환 뒤 어느 브라우저로 돌아오는지. 경로가 추정과 다르면 코드의 `/^\/(login|oauth|shop_join)/` 목록을 고친다.

## 알려진 한계
- **쇼핑몰을 비공개로 되돌리면**(준비중 화면) 그 화면에는 공통 코드가 돌지 않아 로그아웃 뒤 `bd_login`이 최대 7일 남을 수 있다 → 본 사이트에 '마이페이지'가 남는다.
- **v1·v2가 방문자에게 잘못 켠 `bd_login` 쿠키**(2026-10-19~20, 쇼핑몰이 공개된 뒤)는 최대 7일 남는다. 그 방문자가 쇼핑몰을 다시 열면 v2.1이 지우고, 열지 않으면 본 사이트에 '마이페이지'가 보일 수 있다. 쿠키 이름을 바꾸면 한꺼번에 무효화되지만 본 사이트·쇼핑몰 코드를 같이 바꿔야 해서 하지 않았다.
- 쇼핑몰의 로그인 유지 시간이 끝났거나 브라우저를 다시 시작한 뒤, 또는 로그아웃한 뒤 쇼핑몰 화면을 열지 않으면 본 사이트에 '마이페이지'가 최대 7일 남는다. 누르면 아임웹이 로그인으로 보내고, 쇼핑몰 코드가 표시를 지운다.
- 리퍼러가 **도메인만** 전달되는 브라우저는 홈으로 돌아온다. 리퍼러를 **아예 보내지 않는** 설정·확장에서는 돌아오지 않고 쇼핑몰에 머문다(로그인과 마이페이지 전환은 정상).
- 이미 쇼핑몰에 로그인된 채(`bd_login`이 아직 없거나 7일이 지난 첫 방문)로 '로그인'을 누르면, 아임웹이 로그인 화면 대신 쇼핑몰로 보내 돌아오지 못한다(로그인 상태의 `/login`은 쇼핑몰 홈 `/`으로 되돌려진다 — 확인함). 쇼핑몰 화면을 한 번 열면 표시가 켜져 해결된다.
- 돌아오는 시간은 '로그인' 화면에 도착한 뒤 10분 안이다. 가입 메일 인증이나 제공자 앱 전환처럼 오래 걸리는 단계가 생기면 이 시간을 늘린다.
- 리퍼러 없이 `/login`에 들어와(주소 입력·북마크, 리퍼러를 막은 브라우저) 10분 안에 로그인하면, 앞서 남은 복귀 주소(같은 브라우저의 앞 사람이 '로그인'을 누른 화면)로 간다. 취소·앱 전환 뒤일 수 있어 기억을 지우지 않는 선택의 대가다.
- 복귀 주소를 버리는 판단은 로그인·콜백·가입 경로(`/login`·`/oauth`·`/shop_join`로 시작)를 흐름 안으로 본다. 소셜 로그인의 실제 콜백 경로가 다르면, 콜백을 거쳐 가입 화면으로 가는 경우에 한해 복귀가 안 되고 쇼핑몰에 머문다(로그인은 정상, 잘못 튕기는 쪽이 아니라 안전한 쪽).
- 소셜 로그인이 팝업이면 팝업 안에서는 코드가 돌지 않는다(복귀는 원래 창이 맡는다). 팝업이 아닌데 `window.opener`가 있는 창(관리자 '사이트 바로가기' 등을 낡은 브라우저에서 열 때)에서는 코드가 꺼진다 — 요즘 브라우저는 새 탭에 opener를 넘기지 않는다.
- 본 사이트 `/cases/`의 검색어(`?q=`)는 '로그인'을 누르는 순간 리퍼러로 쇼핑몰에 간다(쇼핑몰 코드는 저장 때 지우지만 이미 간 요청은 못 막는다). 지역·단지 이름 수준이고 같은 회사 쇼핑몰로 가는 것이다. 막으려면 `/cases/`가 검색어를 주소에 쓰지 않게 해야 하는데 기능이 바뀌므로 정해진 바가 없다.
- 돌아오는 화면의 `#` 뒤(앵커)는 리퍼러에 실리지 않아 사라진다.
- 휴대폰 폭에서 '마이페이지'는 '로그인'보다 24px 넓다. 360px까지 헤더가 넘치지 않는 것을 확인했다.
