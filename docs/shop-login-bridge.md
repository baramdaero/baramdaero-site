# 쇼핑몰 ↔ 본 사이트 로그인 연결

**상태(2026-10-19): 본 사이트 쪽과 쇼핑몰 Footer Code 모두 적용됨. 쇼핑몰이 비공개라 로그아웃 상태 흐름(로그인 화면에서 복귀 주소 저장 → 로그인 → 복귀 등)은 아직 못 봤다 — 아래 '공개 뒤에 확인할 것'.**

## 하는 일
본 사이트(baramdaero.com) 헤더·푸터의 '로그인'을 누르면 쇼핑몰(shop.baramdaero.com) 로그인 화면으로 가고,
로그인하면 **누르기 전에 보던 본 사이트 화면으로 돌아온다.** 쇼핑몰에서 로그인한 방문자에게는 본 사이트의 '로그인' 자리에 '마이페이지'가 보인다.
둘은 출처가 달라 서로의 로그인 상태를 읽지 못하므로, 아래 두 가지로만 주고받는다.

## 계약
| 무엇 | 누가 | 내용 |
|---|---|---|
| 쿠키 `bd_login=1` | 쇼핑몰이 켜고 끈다, 본 사이트는 읽기만 | 도메인 `.baramdaero.com`, 7일(쇼핑몰 화면을 열 때마다 갱신), `Secure; SameSite=Lax`. 로그인 표시 하나뿐 — 개인정보 없음 |
| 돌아올 화면 | 본 사이트의 '로그인' 링크(`referrerpolicy="unsafe-url"`)가 보던 주소를 리퍼러로 실어 보낸다 | 쇼핑몰이 로그인 화면(`/login`)에서 `document.referrer`를 읽어 쇼핑몰 `sessionStorage`(`bd_return`, 10분)에 둔다 |

이 연결(`src/scripts/shop-session.js`)은 쿠키·저장소에 아무것도 쓰지 않고 `bd_login`을 읽기만 한다. 개인정보 처리방침 §8의 "이 사이트는 쿠키를 직접 저장하지 않습니다"와 맞다.
(사이트의 다른 부분이 쓰는 저장소 — 챗봇 안내 말풍선의 `bd_teaser` 등 — 는 별개이고, §8은 쿠키 문구만 다룬다.)
쇼핑몰이 `bd_login`을 남기는 것은 쇼핑몰 쪽 일이라, 쇼핑몰 방침의 쿠키 문구에 넣을지는 별도 판단이다.

**리퍼러로 가는 정보:** '로그인'을 누르면 지금 보던 화면의 전체 주소(쿼리 포함, `#` 뒤는 제외)가 쇼핑몰(같은 회사 사이트)로 간다.
`/cases/`는 입력한 검색어를 주소(`?q=`)에 쓰므로, 쇼핑몰 코드는 저장하기 전에 `q`를 지운다(지역 `r=` 등은 남겨 돌아온 화면이 같게).

본 사이트 쪽 파일: `src/scripts/shop-session.js`(쿠키 읽기 → `<html class="bd-member">`), `SiteHeader.astro`·`SiteFooter.astro`(링크·표시 전환),
`src/config.js`의 `SHOP_MYPAGE_PATH`(비우면 '마이페이지'·표시·스크립트가 모두 빠지고 '로그인'만 남는다).
검사는 `npm run test:shop` — 링크·CSS·스크립트 위치(`check-shop-links.mjs`), 표시 스크립트(`check-shop-session.mjs`), **이 문서의 쇼핑몰 코드를 그대로 꺼내 돌려 보는 시나리오(`check-shop-bridge.mjs`)**.

## 쇼핑몰 Footer Code (2026-10-19 적용)
설정 > SEO > 고급 설정 > 공통 코드 삽입 > Footer Code. 이미 있던 채널톡 부트 스크립트(680자)는 그대로 두고 **그 아래에 덧붙였다**(총 2205자).
쇼핑몰에 들어간 것은 아래 블록과 같다(1524자, SHA-256 `a48c1bf53dad22429ebff651b69d97e0f68a333f4664e471cf76a54cec768e74`).
검사가 아래 코드를 문서에서 그대로 꺼내 쓰므로, 고칠 때는 이 블록을 고치고 쇼핑몰 Footer Code도 같이 바꾼다.

```html
<script>
/* bd-login-bridge v1 — 본 사이트(baramdaero.com)와 로그인 상태·돌아올 화면을 주고받는다 (docs/shop-login-bridge.md) */
(function () {
  if (window.top !== window.self) return;   // 디자인 모드·미리보기 틀 안에서는 돌지 않는다
  var KEY = 'bd_return';
  var COOKIE = '; domain=.baramdaero.com; path=/; SameSite=Lax; Secure';
  var MAIN = /^https:\/\/(www\.)?baramdaero\.com\//;
  // 로그인한 화면에서만 있는 요소 = '로그아웃' 링크(2026-10-19 관리자 로그인 상태의 홈·마이페이지에서 확인, 로그아웃 상태는 공개 뒤 확인)
  var loggedIn = !!document.querySelector('a[href*="logout"]');
  var ref = document.referrer;
  if (!loggedIn) {
    document.cookie = 'bd_login=; max-age=0' + COOKIE;
    try {
      if (location.pathname === '/login') {
        if (MAIN.test(ref) && !location.search) {
          // 본 사이트의 '로그인'을 눌러 로그인 화면에 막 도착했다 — 그 화면을 기억한다(입력한 검색어 q 는 뺀다)
          var u = new URL(ref);
          u.searchParams.delete('q');
          sessionStorage.setItem(KEY, JSON.stringify({ u: u.href, t: Date.now() }));
        } else if (!/\/login(\?|$)/.test(ref)) {
          // 쇼핑몰 안에서 시작한 로그인, 보호된 화면에서 넘어온 로그인(주소에 쿼리) — 돌아갈 곳을 버린다.
          // 로그인 실패 뒤 다시 열린 /login(리퍼러가 /login)과 가입 화면은 건드리지 않는다
          sessionStorage.removeItem(KEY);
        }
      }
    } catch (e) {}
    return;
  }
  document.cookie = 'bd_login=1; max-age=604800' + COOKIE;
  var saved = null;
  try { var raw = sessionStorage.getItem(KEY); sessionStorage.removeItem(KEY); saved = JSON.parse(raw); } catch (e) {}
  if (saved && Date.now() - saved.t < 600000 && MAIN.test(saved.u)) location.replace(saved.u);
})();
</script>
```

돌려보낼 주소는 `https://baramdaero.com/` 또는 `https://www.baramdaero.com/` 아래만 받는다(다른 주소로 보내는 통로가 되지 않게). 저장된 값을 꺼낼 때도 같은 검사를 한다.

## 확인한 것 (2026-10-19, 코드를 넣은 날, 관리자 로그인 상태)
- **로그인 판별:** 로그인한 쇼핑몰 홈·`/shop_mypage`에서 `a[href*="logout"]`이 4개 잡힌다(`/logout.cm?back_url=…` — 아임웹 `back_url`은 경로를 base64 한 값). 로그인 상태의 화면에는 로그인 링크가 아예 없다(서버가 가려서 그린다).
- **마이페이지 주소:** `/shop_mypage`가 맞다(헤더 메뉴의 `마이페이지` 링크). 로그인한 채 `/login`을 열면 쇼핑몰 홈(`/`)으로 되돌려진다.
- **저장:** 저장 알림을 확인했고, 새로고침 뒤 Footer Code는 2205자, 앞 680자(채널톡)는 그대로, 덧붙인 부분의 해시는 위 값과 같다. Header Code(56,257자)는 건드리지 않았다.
- **실제 화면:** 쇼핑몰 화면에서 스크립트가 한 번 실행되어 `bd_login`이 켜졌고, 본 사이트(`/care/`)의 헤더·푸터가 '마이페이지'로 바뀌었다(`.baramdaero.com` 쿠키를 본 사이트에서 읽음). '마이페이지'를 누르면 쇼핑몰 마이페이지가 열리고 튕기지 않는다. 채널톡도 정상이다.
- **돌아오기(꺼내 쓰는 쪽):** 저장된 복귀 주소가 본 사이트면 로그인된 쇼핑몰 화면을 열자마자 그 화면으로 돌아오고(`/faq/`로 확인), 본 사이트가 아닌 주소(`example.com`)는 따르지 않고 저장값만 지운다.

## 공개 뒤에 확인할 것 (아직 못 본 것)
비공개('사이트 준비중')인 동안 로그아웃 상태의 쇼핑몰 화면은 관리자 로그인 입력 한 칸뿐이고 공통 코드가 돌지 않아, 아래는 공개 뒤에만 볼 수 있다.
1. 로그아웃 상태 화면에서 `a[href*="logout"]`이 하나도 안 잡히는지(로그인 링크가 대신 있는지). 요소가 숨김 처리만 되고 항상 있다면 판별 줄을 바꾸고, `check-shop-bridge.mjs`의 가짜 화면도 같이 고친다.
2. 본 사이트 아무 화면 → '로그인' → 쇼핑몰 `/login`(복귀 주소 저장) → 로그인 → **눌렀던 본 사이트 화면으로 돌아오고** 헤더가 '마이페이지'.
3. 비밀번호를 일부러 틀리고 다시 입력해 로그인 → 그래도 돌아온다.
4. 본 사이트 '로그인' → 쇼핑몰의 가입 화면으로 갔다가 가입 완료 → 돌아온다(가입 후 이동은 '마지막 접속 메뉴'로 켜 둠).
5. 쇼핑몰의 장바구니·구매 화면에서 시작한 로그인은 쇼핑몰에 머문다(본 사이트로 가지 않는다).
6. 쇼핑몰에서 로그아웃 → 본 사이트로 가면 다시 '로그인'(뒤로 가기로 돌아가도 바뀌어 있다).
7. 디자인 모드 편집 화면(틀 안)에서 코드가 돌지 않는지 — `window.top` 검사로 막아 두었다. 편집 중 화면이 튕기면 바로 코드를 지운다.
8. 휴대폰 폭(헤더·푸터 둘 다), 사파리·크롬.

## 알려진 한계
- **비공개(준비중)인 동안:** 로그아웃하면 '사이트 준비중' 화면으로 가서 공통 코드가 돌지 않아 `bd_login`이 최대 7일 남는다 → 본 사이트에 '마이페이지'가 남는다. 공개 뒤 고객에게는 해당 없다(추정 — 로그아웃 상태 화면은 공개 뒤 확인).
- 쇼핑몰의 로그인 유지 시간이 끝났거나 브라우저를 다시 시작한 뒤, 또는 로그아웃한 뒤 쇼핑몰 화면을 열지 않으면 본 사이트에 '마이페이지'가 최대 7일 남는다. 누르면 아임웹이 로그인으로 보내고, 쇼핑몰 코드가 표시를 지운다.
- 리퍼러가 **도메인만** 전달되는 브라우저는 홈으로 돌아온다. 리퍼러를 **아예 보내지 않는** 설정·확장에서는 돌아오지 않고 쇼핑몰에 머문다(로그인과 마이페이지 전환은 정상).
- 이미 쇼핑몰에 로그인된 채(`bd_login`이 아직 없거나 7일이 지난 첫 방문)로 '로그인'을 누르면, 아임웹이 로그인 화면 대신 쇼핑몰로 보내 돌아오지 못한다(로그인 상태의 `/login`은 쇼핑몰 홈 `/`으로 되돌려진다 — 확인함). 쇼핑몰 화면을 한 번 열면 표시가 켜져 해결된다.
- 돌아오는 시간은 '로그인' 화면에 도착한 뒤 10분 안이다. 가입 메일 인증처럼 오래 걸리는 단계가 생기면 이 시간을 늘린다.
- 돌아오는 화면의 `#` 뒤(앵커)는 리퍼러에 실리지 않아 사라진다.
- 휴대폰 폭에서 '마이페이지'는 '로그인'보다 24px 넓다. 360px까지 헤더가 넘치지 않는 것을 확인했다.
